# 로그라이크 던전 크롤링 텍스트 RPG 기획서

> 작성일: 2026-11-19 (v2.2, 로그라이크 + 로그라이트 영구 성장, 일정 11/27 마감 투 트랙) · 기술: Java 17 + Gradle (외부 라이브러리 없음) · 인원: 4명 · 기간: 2026-11-19 ~ 2026-11-27 (평일 7일, 주말은 선택)

## 0. 개정 요약 (v1 → v2)

| 항목 | v1 (일반 텍스트 RPG) | v2 (로그라이크) |
|---|---|---|
| 던전 표현 | 5x5 방 그리드, 방 단위 이동 | **60x20 문자 타일 맵**, 방 + 복도, 한 칸씩 이동 |
| 전투 | 방에 들어가면 별도 전투 화면 | **맵 위에서 몬스터 쪽으로 이동하면 공격(충돌 전투)**, 별도 전투 화면 없음 |
| 몬스터 | 방에 고정 배치 | 맵 위에서 **매 턴 이동** (추적/배회 AI) |
| 아이템 | 보물 방에서 획득 | **바닥에 떨어진 아이템을 주움** |
| 죽음 | 게임 오버 후 세이브 유지 | **영구 죽음**: 사망 시 캐릭터와 진행 중인 탐험은 삭제 |
| 성장 | 캐릭터 레벨업만 | **로그라이트 영구 성장**: 탐험 결과로 "어둠의 파편"을 얻어, 슬롯에 영구히 남는 강화를 구매 |
| 세이브 | 시드 + 방 상태 | 슬롯 = **영구 프로필(파편·강화·기록) + 진행 중인 탐험(맵·몬스터·아이템)**. 사망 시 탐험 부분만 지움 |
| 화면 | 메뉴 위주 | **맵 + 상태줄 + 메시지 로그**를 매 턴 다시 그림 |

> 로그라이크 **장르의 규칙**(무작위 던전, 턴제, 영구 죽음, 문자 그래픽, 미확인 아이템)을 따르되, 게임 이름·세계관·몬스터·최종 목표는 우리 팀의 오리지널로 만든다. 원작의 몬스터 목록이나 목표 아이템을 그대로 가져오지 않는다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 장르 | 콘솔 기반 턴제 로그라이크 던전 크롤러 |
| 가제 | **Into the Dark** |
| 플랫폼 | 터미널(콘솔). 입력은 `Scanner` 한 줄 단위(명령 입력 후 Enter), 출력은 `System.out` |
| 목표 | 매번 새로 생성되는 5개 층을 내려가 최하층의 보스 "어둠의 파수꾼"을 쓰러뜨린다 |
| 플레이 타임 | 클리어 기준 20~40분, 대부분은 중간에 사망 후 재도전 |
| 제약 | 순수 Java 표준 라이브러리만 사용 |

### 1.1 화면 예시

```
 Into the Dark - 지하 2층                                     턴: 214
 ############                 ##########
 #..........#                 #........#
 #...@......+:::::::::::::::::+..G.....#
 #......!...#                 #........#
 #..........#                 #......>.#
 ######+#####                 ##########
       :
       :::::
           :
 HP 32/40 [########--]  MP 5/10  Lv.3  공격 9  방어 4  골드 57
 ------------------------------------------------------------
 > 고블린에게 7의 피해를 입혔다.
 > 고블린이 당신을 공격해 3의 피해를 입었다.
 명령 (w/a/s/d 이동, g 줍기, i 가방, > 내려가기, ? 도움말): _
```

| 기호 | 의미 | 기호 | 의미 |
|---|---|---|---|
| `@` | 플레이어 | `#` | 벽 |
| `:` | 복도 | `.` | 바닥 |
| `+` | 문 | `>` | 아래층 계단 |
| `!` | 물약 | `?` | 두루마리 (P1) |
| `)` | 무기 | `[` | 방어구 |
| `%` | 음식 (P1) | `$` | 골드 |
| `A~Z` | 몬스터 (영문 첫 글자) | `&` | 보스 (어둠의 파수꾼) |

### 1.2 게임 흐름

```
타이틀 → 슬롯 선택(1~3, 빈 슬롯이면 새 프로필 생성)
  → 슬롯 메뉴: 새 탐험 / 이어하기(진행 중인 탐험이 있을 때) / 어둠의 제단(영구 강화) / 기록 / 뒤로
  → 새 탐험: 이름·직업 선택(해금된 직업만) → 영구 강화 적용된 캐릭터로 시작
  → 층 생성(방 + 복도) → 턴 루프
       ① 맵·상태·로그 출력
       ② 플레이어 명령 1개 입력 (이동/공격/줍기/사용/장착/계단/저장)
       ③ 명령이 턴을 소모했다면 모든 몬스터가 1번씩 행동
       ④ 사망 확인
  → `>` 위에서 내려가기 → 다음 층 (5층 보스 처치 시 클리어)
  → 사망 또는 클리어: 결과 화면 + 획득 파편 정산 → 캐릭터·탐험 삭제, 파편·기록은 슬롯에 저장
  → 슬롯 메뉴로 돌아가 제단에서 강화 → 다시 도전 (반복)
```

### 1.3 턴 규칙
- 이동, 공격, 아이템 사용, 줍기, 장착, 계단 내려가기 = **턴 소모**
- 가방 보기, 도움말, 상태 보기 = 턴 소모 없음
- 몬스터 쪽으로 이동하면 이동 대신 공격한다. 몬스터도 플레이어와 붙어 있으면 공격, 아니면 이동한다.

## 2. 필수 요소와 중요도

중요도 기준
- **P0 (필수)**: 없으면 게임이 성립하지 않음. 11/25(수)까지 완성 (주말 작업 시 11/24).
- **P1 (중요)**: 로그라이크다운 재미를 주는 요소. MVP 직후 구현.
- **P2 (선택)**: 시간이 남으면 구현.

### 2.1 던전 · 맵 (D 파트)

| 기능 | 설명 | 중요도 |
|---|---|---|

### 2.6 영구 성장 (로그라이트, 필수)

캐릭터는 죽으면 사라지지만, 탐험 결과에 따라 **어둠의 파편**을 얻고 슬롯에 영구히 쌓인다. 파편으로 슬롯 메뉴의 **어둠의 제단**에서 강화를 사면 이후 모든 탐험에 적용된다.

| 기능 | 설명 | 중요도 |
|---|---|---|
| 파편 정산 | 사망·클리어 시 결과에 따라 파편 지급, 결과 화면에 항목별 내역 표시 | P0 |
| 영구 강화 4종 | 최대 HP, 공격, 방어, 시작 물약 (아래 표) | P0 |
| 강화 적용 | 새 탐험 시작 시 `Player` 생성 직후 강화 수치 반영 | P0 |
| 프로필 기록 | 총 탐험 수, 최고 도달 층, 클리어 수, 누적 처치 수 | P0 |
| 직업 해금 | 처음엔 전사만, 마법사·도적은 파편으로 해금 | P1 |
| 추가 강화 3종 | 가방 칸, 경험치 획득량, 파편 획득량 | P1 |
| 업적 보너스 | "처음으로 3층 도달" 같은 1회성 파편 보너스 | P2 |

**파편 획득 공식 (초안)**

| 항목 | 파편 |
|---|---|
| 도달한 가장 깊은 층 | 층 × 10 |
| 처치한 몬스터 | 마리당 1 |
| 최종 레벨 | 레벨 × 3 |
| 들고 있던 골드 | 골드 ÷ 10 |
| 보스 처치(클리어) | +100 |
| 탐험 포기(새 탐험으로 덮어쓰기) | 0 (포기 시 파편 없음) |

> 예: 3층에서 처치 14, 레벨 4, 골드 57로 사망 → 30 + 14 + 12 + 5 = **61 파편**

**영구 강화 목록 (초안)**

| 강화 | 효과 / 단계 | 최대 | 비용 (단계별) | 중요도 |
|---|---|---|---|---|
| 강인한 육체 | 최대 HP +5 | 5단계 | 20 / 40 / 60 / 80 / 100 | P0 |
| 날카로운 칼날 | 공격 +1 | 3단계 | 30 / 60 / 90 | P0 |
| 단단한 피부 | 방어 +1 | 3단계 | 30 / 60 / 90 | P0 |
| 보급품 | 시작 시 치유 물약 +1 | 2단계 | 25 / 50 | P0 |
| 큰 가방 | 가방 칸 +2 | 2단계 | 40 / 80 | P1 |
| 배움의 축복 | 경험치 획득 +10% | 3단계 | 35 / 70 / 105 | P1 |
| 파편 수집가 | 파편 획득 +10% | 3단계 | 50 / 100 / 150 | P1 |
| 직업 해금: 마법사 | 마법사 선택 가능 | 1 | 60 | P1 |
| 직업 해금: 도적 | 도적 선택 가능 | 1 | 60 | P1 |

> 밸런스 목표: 강화 없이도 클리어는 가능하지만 어렵고(첫 시도 대부분 2~3층 사망), 5~8회 도전 후 P0 강화를 대부분 사면 클리어가 현실적인 수준.

| 제단 구매 저장 | 강화 구매 즉시 프로필 저장 | P0 |
| 오류 처리 | 파일 없음·손상·버전 불일치 시 안내 후 메인 메뉴 | P0 |
| 랭킹 | 사망/클리어 시 점수(골드 + 층×100 + 레벨×50)를 `saves/ranking.txt`에 기록, 상위 10개 표시 | P1 |

**저장 방식**
- `java.nio.file.Files` + UTF-8 텍스트. `[섹션]` + `key=value` 형식, 직접 파싱. (`Serializable`은 클래스 변경 시 깨지므로 사용 안 함)
- 파일은 **프로필 섹션**(`[PROFILE]`, `[UPGRADES]`)과 **탐험 섹션**(`[RUN]`, `[PLAYER]`, `[INVENTORY]`, `[IDENTIFY]`, `[FLOOR]`, `[MONSTERS]`, `[ITEMS]`)으로 나뉜다. 탐험 섹션은 진행 중인 탐험이 있을 때만 존재한다.
- 현재 층의 **맵 타일, 탐험 기록, 살아 있는 몬스터, 바닥 아이템**을 그대로 기록한다. 지나온 층은 돌아갈 수 없으므로 저장하지 않고, 다음 층은 내려갈 때 새로 생성한다. → 시드 재현이 필요 없어 구현이 단순하다.
- `slotN.sav.tmp`에 먼저 쓰고 `Files.move(..., REPLACE_EXISTING, ATOMIC_MOVE)`로 교체 → 저장 중 꺼져도 기존 세이브 보존. 파편이 걸려 있어서 이 처리가 특히 중요하다.
- 영구 죽음 보장: 이어하기로 탐험을 불러온 뒤 플레이 중 강제 종료하면 마지막 저장 시점에서 다시 시작되지만, 사망하는 순간 즉시 탐험 섹션을 지우고 저장하므로 죽음을 되돌릴 수 없다.

**세이브 파일 예시 (`saves/slot1.sav`)**

```ini
# Into the Dark Save File
[META]

# ===== 영구 프로필 (사망해도 유지) =====

# ===== 진행 중인 탐험 (사망·클리어 시 아래 전부 삭제) =====

turn=214
kills=9

[PLAYER]

job=WARRIOR

exp=40

maxHp=40
```

**파싱 규칙**
- `#`으로 시작하는 줄과 빈 줄은 무시, `[이름]`은 섹션 시작, 그 외는 첫 `=` 기준으로 key/value 분리.
- 같은 key가 반복되는 `item=`, `monster=`은 리스트로 읽는다.
- `[RUN]` 섹션이 없으면 "진행 중인 탐험 없음"으로 본다.
- `[UPGRADES]`에 없는 강화는 0단계, 모르는 강화 id는 무시(나중에 강화가 추가돼도 기존 세이브 유지).
- 필수 key 누락, 숫자 변환 실패, 맵 줄 길이 불일치 시 `SaveLoadException` → "세이브 파일이 손상되었습니다" 출력 후 메인 메뉴. 탐험 섹션만 손상됐다면 프로필은 살리고 탐험만 버릴지 묻는다.

**파트 간 의존 관계**
- C의 AI는 D의 `Floor.isWalkable()`, `Floor.getMonsterAt()`에 의존 → D가 11/20에 시그니처를 먼저 푸시

- 세이브는 A가 파일 형식을 맡고, B·C·D는 자기 객체의 상태를 꺼내고 복원하는 getter·생성자만 제공
- 영구 성장은 B가 규칙(`Profile`, `UpgradeType`, `ShardCalculator`, `Profile.applyTo(player)`)을 맡고, A가 제단 화면과 저장을 맡는다. 처치 수 집계는 C의 `CombatSystem.rewardKill()`에서 `RunResult.addKill()` 호출
- B의 작업량이 늘어났으므로, MVP 이후 P1에서 미확인 아이템·두루마리는 C가 도울 수 있게 미리 합의
